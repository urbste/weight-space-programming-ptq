- **Scale per row:** the row's largest absolute folded weight divided by 7, so the biggest weight lands on code ±7 and the full 4-bit range is used.

- **Why:** with no data and no way to run the network, max-abs scaling with round-to-nearest minimizes the worst-case rounding error per row. It avoids clipping and doesn't depend on any assumption about activations. It is essentially plain round-to-nearest, so I don't expect it to beat the baseline by much. I did no error compensation, and nothing here is verified by running the network.
- **Risk:** I computed the roundings by hand, so a few codes may be off by one, mostly at near-tie values.
