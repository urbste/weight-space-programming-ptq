## Summary

**What changed:** Edits were made only to conv1 (rows 0, 2, 3, 7) and fc (rows 1, 2, 4, 6, 7, 8, 9). Each changed row uses a scale of 0.9 times the RTN scale, with codes re-rounded to the nearest integer for that smaller step. Biases are unchanged. Conv2, conv3, conv4 and the remaining conv1 and fc rows stay at RTN.

**Why:** The RTN scale is max|w|/7, which lets a single outlier set the step for the whole row. For each row I compared the total squared weight error (in units of the RTN step) for scale 1.0 and scale 0.9, using the given u values. I kept whichever was lower. Scale 0.9 reduced that error in conv1 rows 0, 2, 3 and 7, and in fc rows 1, 2, 4, 6, 7, 8 and 9. In the other rows it was equal or worse, so they stay at RTN. The largest gains were in fc rows 6 and 9 and in conv1 row 2.

**Limits:** This is weight-space error only. I cannot run the network, so there is no accuracy estimate. Weight error is a proxy, and the 0.9 choice is not validated against activations or labels. Searching conv2 to conv4 row by row was too large to do reliably by hand (roughly 2,300 to 9,000 weights per chunk), so those layers got no edits. Arithmetic was done by hand, so small rounding slips are possible.
